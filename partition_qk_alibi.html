Routing queries to KV-cache partitions

The parition_qk_alibi family tested learned sparse attention: each query routes to a small set of partitions of the KV cache instead of attending densely, on top of ALiBi. Six branches were tried — parition_qk_alibi, _embed, _embed_mlp_q, _embed_post_training, _embed_post_training_no_stats, _embed_post_training_retrieval_penalty. Across 75 runs on three datasets, no configuration beat — or matched — the dense ALiBi baseline it started from.

Hard partition routing is the intended inference behavior: at deployment each query attends only within its routed partition(s), so evaluation correctly forces the hard mask. The failure has two layers. First, most from-scratch configs set the mask-activation schedule to 1.0, so the hard mask was never used during training — the model trained dense and met its own routing for the first time at eval, producing a large, seed-dependent train/eval gap. Schedules that do reach the hard mask during training close that gap to ≈0. What remains once the gap is closed is the method’s real ceiling: matched-schedule and post-training runs are consistent train-to-eval but still land ~0.1–0.4 nats above dense, because the routing objective and masked-attention math (defects #2–#5 below) cannot learn a sparse pattern that preserves quality.

Mechanism

Per attention layer, on top of standard ALiBi causal attention, new routing weights produce two soft assignments over n_partitions:

\[ \texttt{q\_gate} = \sigma(g_x \cdot W_q + b_q) \in [0,1]^{n_\text{part}}, \qquad \texttt{k\_route} = \mathrm{softmax}(g_x \cdot W_k) \in \Delta^{n_\text{part}} \]

where \(g_x\) is the layer input embedding. Their outer product over partitions gives a soft keep-probability per (query, key) pair, softmask, combined with the causal mask. A hard variant — q_gate > hard_q_threshold and \(\arg\max\) over k_route — is the inference path (the actual KV-cache saving), so eval forces it via total_steps=0. Routing weights are trained by auxiliary terms (recall_loss, retrieve_loss), not by the LM loss directly.

Two step-gated switches control when the masks enter the forward pass:

  • apply_softmask activates at step >= softmask_start_fraction * total_steps
  • apply_hardmask activates at step >= hardmask_start_fraction * total_steps

The lineage adds incrementally: _embed routes off \(g_x\) instead of \(q/k\); _mlp_q adds an MLP for the query gate; _post_training freezes a pretrained dense model and fine-tunes only the routing weights; _no_stats removes diagnostic logging only (no training change); _retrieval_penalty adds a sparsity-vs-recall budget loss.

Code defects

Branch line references are on the old_experiments remote (github.com/clankur/experimental). Each defect maps to a measured failure signature below.

This is a schedule/protocol choice, not a code bug — and the fix is on the training side. from-scratch configs (*_start_fraction) train ≈ dense, eval blows up & seed-dependent — but only at hard_frac=1.0; schedules that reach the hard mask in training close the gap (below)

def calculate_ema(data, smoothing=0.97):
    ema = [data[0]]
    for value in data[1:]:
        ema.append(ema[-1] * smoothing + value * (1 - smoothing))
    return ema


def _read_csv(path):
    if not path.exists():
        return None
    rows = list(csv.DictReader(open(path)))
    if not rows:
        return None
    steps = [int(float(r["step"])) for r in rows]
    vals = [float(r["value"]) for r in rows]
    return steps, vals


def _config(metadata):
    cfg = {}
    for k, v in metadata.get("hyperparameters", {}).items():
        if k.startswith("Hydra/model.") or k.startswith("Hydra/training."):
            cfg[k.split(".", 1)[1]] = v
    return cfg


def _load_run(run_dir):
    md = json.loads((run_dir / "metadata.json").read_text())
    m = run_dir / "metrics"
    train = _read_csv(m / "loss_loss.csv")
    pt = _read_csv(m / "post_train_loss_post_train_loss.csv")
    pt_total = _read_csv(m / "post_train_total_loss_post_train_total_loss.csv")
    ev = _read_csv(m / "final_loss_eval.csv")
    ppl = _read_csv(m / "final_perplexity_eval.csv")
    cfg = _config(md)
    return {
        "name": md["experiment_name"],
        "status": md["status"],
        "config": cfg,
        "train_steps": train[0] if train else None,
        "train_loss": train[1] if train else None,
        "train_ema": calculate_ema(train[1])[-1] if train else None,
        "pt_steps": pt[0] if pt else None,
        "pt_loss": pt[1] if pt else None,
        "pt_total_loss": pt_total[1] if pt_total else None,
        "pt_start": pt[1][0] if pt else None,
        "pt_end": calculate_ema(pt[1])[-1] if pt else None,
        "eval": ev[1][-1] if ev else None,
        "ppl": ppl[1][-1] if ppl else None,
        "n_part": int(cfg.get("n_partitions", 0)),
        "soft_frac": float(cfg.get("softmask_start_fraction", -1)),
        "hard_frac": float(cfg.get("hardmask_start_fraction", -1)),
        "ptm": float(cfg["post_training_mult"]) if "post_training_mult" in cfg else None,
        "rscale": float(cfg["retrieval_scale"]) if "retrieval_scale" in cfg else None,
        "variant": cfg.get("variant", ""),
        "apply_alibi": cfg.get("apply_alibi", "True"),
    }


def load_segment(dataset, segment):
    return [_load_run(d) for d in sorted((ROOT / SEGMENTS[(dataset, segment)]).iterdir()) if d.is_dir()]


def short_variant(v):
    return (v.replace("embedding_routed_partition", "routed")
             .replace("new_softmask_probs_budget", "softmask_budget")
             .replace("new_softmask_probs", "softmask")
             .replace("retrieve_penalty_", "")
             .replace("\\", "") or "default")

Training looks healthy: from-scratch runs track the dense baseline

On c4, the from-scratch partition runs train to the same loss as dense ALiBi — because with softmask_start_fraction = hardmask_start_fraction = 1.0 the routing masks are never in the forward path during training (defect #1). The model is plain dense ALiBi attention throughout. Runs that turn masking on earlier (soft=0.5/hard=0.8) are visibly worse, the only effect of the routing being to degrade the CE it cannot receive gradient for (defects #3, #4).

Matching the schedule closes the gap

Grouping the c4 from-scratch runs by hardmask_start_fraction shows the gap is a schedule artifact, not an inherent property of hard routing. Whenever the hard mask is reached before the end of training (hard_frac < 1.0), eval tracks training to within 0.06 — exactly as it should, since train and eval then use the same routing. Only the hard_frac = 1.0 runs (hard mask never trained) diverge, and they do so catastrophically and seed-dependently when the routing weights are left effectively untrained (the partition_disabled seed at eval 6.2).

Code 
runs = load_segment("c4", "base") + load_segment("c4", "embed")
rows = []
for r in runs:
    if r["train_ema"] is None or r["eval"] is None:
        continue
    rows.append({"variant": short_variant(r["variant"]),
                 "soft_frac": r["soft_frac"], "hard_frac": r["hard_frac"],
                 "train": round(r["train_ema"], 2), "eval": round(r["eval"], 2),
                 "gap": round(r["eval"] - r["train_ema"], 2)})
df = pd.DataFrame(rows).sort_values(["hard_frac", "gap"]).reset_index(drop=True)
df.style.format(precision=2).set_caption(
    "c4 from-scratch: train/eval gap by mask schedule. hard_frac<1.0 (hard mask trained) → gap≈0; hard_frac=1.0 (never trained) → mismatch.")

The cost of matching is absolute quality: training through the hard mask pulls the eval loss to 3.55–3.74 versus dense 3.49. The mismatch is removable; the ~0.1–0.25-nat deficit is the routing mechanism’s ceiling. The un-renormalized masked attention (defect #2) is what makes the unmatched hard_frac=1.0 case so violent and seed-dependent rather than merely worse.

The slim runs make the dependence on the routing variant explicit: variants that retrieve nearly all keys (soft_retrieve_gx/nx, low scale) stay near the baseline; the plain routed variant at 512 partitions collapses to eval 4.4–4.6.

Post-training: loss only ever rises

Post-training is the clean test of the ceiling: these runs use softmask_start_fraction=0.0 and hardmask_start_fraction=0.9, so they train through the soft mask and into the hard mask — there is no train/eval mismatch here, and indeed the post-training CE end and the hard eval agree (e.g. 3.33 vs 3.37). Freezing a pretrained dense model and fine-tuning only the routing weights (_post_training) still cannot recover the attention quality lost to the partition mask. On longcrawl, every run’s post-training CE rises monotonically from its step-0 minimum (the dense starting point) — the mis-horizoned LR schedule (defect #6) and the collapse-rewarding objective (#3, #4) push the loss up, not down. The best partition result (n_part=128, post_training_mult=0.25) reaches eval 3.37, still +0.2 nats above the dense baseline of 3.17.

The retrieval penalty optimizes the wrong thing

The _retrieval_penalty branch adds retrieve_loss = mean_layers log(retrieved_fraction), a negative quantity that is added to the loss — so total loss drops when the model retrieves fewer keys, regardless of CE. The plot below shows the trap directly: total loss (with the penalty) falls below zero while the actual CE climbs. The optimizer is cashing in language-modeling quality for the sparsity reward (defect #3). The two runs where routing genuinely engaged reached eval perplexity 12k–13k (CE ≈ 9.5, near random init).

Limitations

  • All runs are 31M parameters; c4/slim at \(L=1024\), longcrawl at long context. The mechanism could behave differently at scale.
  • Many runs are marked failed in ClearML but completed training and the final eval — the crash is a checkpoint-upload/teardown error after metrics were logged. Their eval numbers are valid and are used here.
  • The from-scratch runs almost all used *_start_fraction = 1.0, so the soft→hard annealing schedule was never actually trained through. No run combines early soft-masking, renormalized probabilities, and a load-balanced objective — i.e. the corrected design was never tested.
  • No KV-cache memory or latency was measured; results are loss-only.

What a corrected experiment would need

Fix Defect addressed
Train through the hard mask — keep hard eval, but set hardmask_start_fraction < 1.0 (or use a straight-through estimator) so training sees the routing it is graded on #1
Re-softmax (renormalize) attention after masking #2
Add a load-balancing / entropy term; remove the sign-flipped budget reward #3
Let CE flow into the routing (drop stop_gradient on probs) #4
Make the gate bias an annealed hparam, not a hardcoded constant #5
Use a proper post-training LR horizon (steps_for_lr = steps//3) #6
Fix the grad-norm exclusion to the real weight names #7
